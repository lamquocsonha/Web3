Unilab Deployment
v1.0 — CentOS 7 / Vultr

Khi deploy rồi, có cần chạy run.bat không?

Không. Khi deploy lên server (VPS/Vultr), run.bat hoàn toàn không cần dùng. Trên production, ứng dụng được chạy bởi Gunicorn (WSGI server chuyên dụng) thông qua systemd service — hệ thống tự động khởi động app khi server bật, tự restart khi app crash, và chạy nền 24/7 mà không cần mở terminal.

run.bat chỉ dành cho môi trường phát triển trên Windows (localhost).

2

Upload source code lên server

Dùng SCP hoặc Git để copy toàn bộ thư mục V00 lên VPS.

# Option 1: SCP (nhanh nhất)
ssh root@IP_SERVER "mkdir -p /var/www/unilab"
scp -r V00/* root@IP_SERVER:/var/www/unilab/

# Option 2: Git
ssh root@IP_SERVER
git clone https://github.com/username/Web3.git /tmp/web3
cp -r /tmp/web3/V00/* /var/www/unilab/

sudo bash deploy.sh

Script sẽ hỏi domain (VD: unilab.vn) và có muốn cài SSL không.

Tại sao không dùng run.bat trên server?
1. run.bat là file Windows, server là Linux
File .bat là định dạng script của Windows, không chạy được trên Linux. Server VPS (CentOS/Ubuntu) dùng bash script (.sh).
2. Flask dev server không dùng cho production
run.bat chạy python app.py → khởi động Flask built-in server (Werkzeug) với debug=True. Server này:
• Chỉ xử lý 1 request tại 1 thời điểm
• Bật debug mode = lộ thông tin nhạy cảm nếu có lỗi
• Không ổn định cho traffic thực tế

Trên production, Gunicorn thay thế hoàn toàn vai trò này — chạy 2 worker x 2 thread, xử lý nhiều request đồng thời, ổn định và an toàn hơn.
3. systemd thay thế vai trò "bấm run" thủ công
Trên local, anh phải bấm run.bat mỗi lần muốn chạy app. Trên server, systemd làm việc này tự động:
• Server bật → app tự khởi động
• App crash → tự restart sau 5 giây
• Tắt SSH terminal → app vẫn chạy bình thường
• 24/7 không cần ai giám sát
4. Gunicorn import trực tiếp app object, bỏ qua if __name__ == '__main__'
Lệnh Gunicorn: gunicorn app:app nghĩa là import biến app từ file app.py. Nó không chạy if __name__ == '__main__' (block này chỉ chạy khi gọi python app.py trực tiếp). Do đó, Gunicorn sẽ không auto-open browser, không bật debug mode — đúng hành vi production cần.

1

Kiểm tra / Cài Python 3.8+

CentOS 7 mặc định có Python 3.6 (quá cũ). Script sẽ tự cài Python 3.8/3.9/3.11 nếu cần.

2

Chuẩn bị thư mục /var/www/unilab

Kiểm tra source code đã được copy lên chưa. Nếu chưa thì dừng lại để copy.

3

Tạo venv + cài dependencies

Tương đương với install.bat trên Windows, nhưng dùng Linux commands. Cài thêm gunicorn.

python3 -m venv venv
pip install -r requirements.txt
pip install gunicorn
4

Khởi tạo database

Tạo bảng trong SQLite (giống lúc python app.py lần đầu trên local).

5

Tạo systemd service

Đăng ký app như một "service" của hệ điều hành — giống như cài một phần mềm chạy nền trên Windows.

# File được tạo tại:
/etc/systemd/system/unilab.service

# Lệnh chạy app:
gunicorn --workers 2 --threads 2 --bind 127.0.0.1:8000 app:app
6

Cấu hình Nginx (reverse proxy)

Nginx nhận request từ browser (port 80/443) rồi chuyển đến Gunicorn (port 8000). Nginx cũng phục vụ file tĩnh (CSS, JS, images) nhanh hơn.

7

Khởi động app + SSL (tuỳ chọn)

Bật service, reload Nginx, và tuỳ chọn cài SSL Let's Encrypt miễn phí.

systemctl restart unilab
systemctl status unilab
Nginx phân luồng traffic thế nào?

Cả 2 site dùng chung 1 Nginx. Nginx dựa vào domain name trong request để chuyển đến đúng backend.

/etc/nginx/conf.d/tripzone.conf
server {
  listen 80;
  server_name tripzone.vn;
  ...
  # → PHP-FPM backend
}
/etc/nginx/conf.d/unilab.conf
server {
  listen 80;
  server_name unilab.vn;
  ...
  location / {
    proxy_pass http://127.0.0.1:8000;
  }
}
Request flow:
User → tripzone.vn → Nginx → PHP-FPM → TripZone response
User → unilab.vn → Nginx → Gunicorn :8000 → UniLab response

Theo dõi log trực tiếp. Ctrl+C để thoát.

Dừng app tạm thời. Dùng start để chạy lại.

# Upload code mới
scp -r V00/* root@server:/var/www/unilab/

systemctl restart unilab

Lưu ý quan trọng

  • Không bật debug=True trên production — Gunicorn tự tắt debug, nhưng nếu sửa app.py, đừng hardcode debug=True ở ngoài block if __name__.
  • Backup database thường xuyên — SQLite là 1 file duy nhất (instance/unilab.db), dễ mất nếu server hỏng.
  • SSL/HTTPS — Nên cài Let's Encrypt (miễn phí) để bảo mật. Script deploy.sh có hỗ trợ sẵn.
  • Khi thay đổi requirements.txt — Cần SSH vào server, activate venv, chạy pip install -r requirements.txt rồi restart.
Tóm tắt
Local (Windows):
Chạy install.bat (1 lần) → Chạy run.bat (mỗi lần muốn dev) → Flask dev server trên port 7000 → Tắt terminal = app tắt.

Production (Server):
Upload code → Chạy deploy.sh (1 lần) → Gunicorn + Nginx chạy 24/7 → systemd tự quản lý → Không cần run.bat, không cần mở terminal.
