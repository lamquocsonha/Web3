🚀 Deploy UniLab chung với TripZone (CentOS 7)

Server Vultr đã có TripZone — thêm UniLab chạy song song, không ảnh hưởng nhau

💡 Khi deploy rồi, có cần chạy run.bat không?

Không. Khi deploy lên server (VPS/Vultr), run.bat hoàn toàn không cần dùng. Trên production, ứng dụng được chạy bởi Gunicorn (WSGI server chuyên dụng) thông qua systemd service — hệ thống tự động khởi động app khi server bật, tự restart khi app crash, và chạy nền 24/7 mà không cần mở terminal.

run.bat chỉ dành cho môi trường phát triển trên Windows (localhost).

🔍 Tại sao không dùng run.bat trên server?

1. File .bat là của Windows
File .bat là định dạng script Windows, không chạy được trên Linux. Server dùng bash script (.sh).
2. Flask dev server không an toàn
run.bat chạy python app.py với debug=True — lộ thông tin nhạy cảm, chỉ 1 thread, không ổn định.
3. systemd thay thế "bấm run"
Server bật → app tự chạy. App crash → tự restart. Tắt SSH → app vẫn chạy 24/7 không cần ai giám sát.
4. Gunicorn bỏ qua if __name__
gunicorn app:app import trực tiếp app object — không chạy block if __name__ == '__main__', không auto-open browser.

Trỏ Domain UniLab về Server

💡 Lưu ý:
Dùng cùng IP server với TripZone. Nginx sẽ phân biệt traffic bằng domain name (server_name). TripZone và UniLab cùng IP nhưng khác domain → không xung đột.
Vào quản lý DNS của domain UniLab, thêm A records:
Type Name / Host Value / Points To TTL Mục đích
A @ IP_SERVER_VULTR 3600 unilab.vn (domain gốc)
A www IP_SERVER_VULTR 3600 www.unilab.vn
Kiểm tra DNS đã trỏ đúng:
ping unilab.vn
# Phải thấy IP trùng với server Vultr (cùng IP với TripZone)
⏱️ DNS thường mất 5-30 phút để có hiệu lực. Có thể deploy song song trong khi chờ.

Chạy Script Deploy

⚠️ Quan trọng:
Script deploy.sh đã được viết riêng cho CentOS 7 và sẽ không ảnh hưởng TripZone.
Script chỉ tạo thêm: virtual environment Python, Gunicorn service (port 8000), Nginx config mới.
SSH vào server và chạy:
ssh root@IP_SERVER

cd /var/www/unilab
chmod +x deploy.sh
sudo bash deploy.sh
🔄 Script tự động làm 7 bước:
  1. Kiểm tra Python — Cài Python 3.8+ nếu CentOS 7 chỉ có 3.6
  2. Chuẩn bị thư mục — Kiểm tra source code tại /var/www/unilab
  3. Virtual environment — Tạo venv riêng + cài dependencies (Flask, Gunicorn,...)
  4. Database — Khởi tạo SQLite database (instance/unilab.db)
  5. Systemd service — Tạo unilab.service chạy Gunicorn trên port 8000
  6. Nginx config — Tạo /etc/nginx/conf.d/unilab.conf (hỏi domain)
  7. Khởi động — Start UniLab service + reload Nginx
Khi script hỏi domain:
Nhập domain cho UniLab (VD: unilab.vn):
> unilab.vn

# Gõ domain rồi nhấn Enter
Khi script hỏi SSL:
Cài SSL (Let's Encrypt)? (y/n)
> y

# Gõ 'y' nếu DNS đã trỏ đúng (chờ ít nhất 30 phút sau khi setup DNS)
# Gõ 'n' nếu muốn dùng HTTP tạm

🔀 Nginx phân luồng traffic thế nào?

Cả 2 site dùng chung 1 Nginx. Nginx dựa vào domain name trong request để chuyển đến đúng backend. Mỗi site có 1 file config riêng trong /etc/nginx/conf.d/:

/etc/nginx/conf.d/tripzone.conf
server {
  listen 80;
  server_name tripzone.vn;
  ...
  # → PHP-FPM backend
}
/etc/nginx/conf.d/unilab.conf
server {
  listen 80;
  server_name unilab.vn;
  ...
  location / {
    proxy_pass http://127.0.0.1:8000;
  }
}
Request flow:
User → tripzone.vn → Nginx → PHP-FPM → TripZone response
User → unilab.vn → Nginx → Gunicorn :8000 → UniLab response

🔧 Xử lý lỗi thường gặp

❌ UniLab 502 Bad Gateway
Gunicorn chưa chạy hoặc bị crash
systemctl status unilab
# Nếu inactive/failed:
systemctl restart unilab
journalctl -u unilab -n 50 # Xem lỗi
⚠️ TripZone bị ảnh hưởng sau deploy
Rất hiếm — thường do Nginx config bị syntax error
# Test config Nginx:
nginx -t

# Nếu lỗi, xem file config UniLab:
cat /etc/nginx/conf.d/unilab.conf

# Tạm tắt UniLab config nếu cần khôi phục TripZone:
mv /etc/nginx/conf.d/unilab.conf /etc/nginx/conf.d/unilab.conf.bak
systemctl reload nginx
# → TripZone sẽ hoạt động lại ngay
⚠️ SSL certificate lỗi
DNS chưa trỏ đúng hoặc port 80 bị block
# Kiểm tra DNS:
ping unilab.vn

# Kiểm tra firewall (CentOS 7 dùng firewalld):
firewall-cmd --list-all
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload

# Setup SSL lại:
certbot --nginx -d unilab.vn -d www.unilab.vn

⚠️ Lưu ý quan trọng

  • Không bật debug=True trên production — Gunicorn tự tắt debug, nhưng nếu sửa app.py, đừng hardcode debug=True ở ngoài block if __name__.
  • Backup database thường xuyên — SQLite là 1 file duy nhất (instance/unilab.db), dễ mất nếu server hỏng.
  • SSL/HTTPS — Nên cài Let's Encrypt (miễn phí) để bảo mật. Script deploy.sh có hỗ trợ sẵn.
  • Khi thay đổi requirements.txt — Cần SSH vào server, activate venv, chạy pip install -r requirements.txt rồi restart.

📋 Tóm tắt

Local (Windows):
Chạy install.bat (1 lần) → Chạy run.bat (mỗi lần muốn dev) → Flask dev server trên port 7000 → Tắt terminal = app tắt.

Production (Server):
Upload code → Chạy deploy.sh (1 lần) → Gunicorn + Nginx chạy 24/7 → systemd tự quản lý → Không cần run.bat, không cần mở terminal.
